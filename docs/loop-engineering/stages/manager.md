# 05 — Gestionnaire

## Finalité

Transformer le travail restant et les retours de vérification en un **ordre de priorité explicite et maîtrisé**.

## Responsabilités

- normaliser le backlog ;
- évaluer valeur, risque, urgence et coût du délai ;
- tenir compte des dépendances ;
- appliquer les limites de travail en cours ;
- sélectionner le prochain lot ;
- différer ou escalader les éléments non actionnables.

## Critères de priorisation

| Critère | Question |
|---|---|
| Valeur | Quel bénéfice rapproche le plus de l'objectif ? |
| Risque | Quelle action réduit le plus tôt une incertitude importante ? |
| Urgence | Existe-t-il une échéance ou un coût du délai ? |
| Dépendances | Quelle tâche débloque le plus de travail ? |
| Effort | Quel est le coût estimé de l'action ? |
| Confiance | Les informations sont-elles suffisantes pour décider ? |

## Sorties obligatoires

- backlog priorisé ;
- prochain lot de travail ;
- éléments différés et justification ;
- escalades nécessaires ;
- limites WIP applicables.

## Règles

1. Le nombre de tâches actives doit rester limité.
2. Un blocage doit être rendu visible.
3. La priorité doit pouvoir être expliquée.
4. Le risque et l'apprentissage peuvent primer sur le débit.
5. Une tâche non prête ne doit pas entrer dans l'exécution.

## Anti-patterns

- priorité basée uniquement sur l'ancienneté ;
- trop grand nombre de tâches simultanées ;
- absence de traitement des dépendances ;
- urgences permanentes non arbitrées ;
- réordonnancement sans justification.
